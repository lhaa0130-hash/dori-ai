월 1만 원으로 AI 어디까지 붙일 수 있나 — 예산별 모델 조합 설계

2026년 8월 13일 by illo
공유하기

들어가며: 월 1만 원은 생각보다 큰 돈입니다

AI를 서비스에 붙이려는 사람이 가장 먼저 하는 걱정은 "돈이 얼마나 깨질까"입니다. 그런데 실제로 계산해 보면 작게 시작하는 데는 돈이 거의 안 듭니다.

이 글은 **월 1만 원(약 $7)**이라는 구체적인 예산 하나를 놓고, 그 돈으로 무엇을 얼마나 할 수 있는지 실제 단가로 계산한 것입니다. 그리고 같은 예산으로 3.5배를 더 쓰는 설계까지 다룹니다.

숫자는 AI 모델 가격 비교 · 비용 계산기에서 쓰는 것과 같은 실단가입니다. 환율은 1,400원/달러 기준으로 잡았습니다.

1. $7로 실제로 무엇을 할 수 있나

세 가지 전형적인 작업을 기준으로 잡았습니다.

  • 챗봇 1회 — 입력 500 + 출력 300 토큰
  • 요약 1건 — 입력 8,000 + 출력 500 토큰
  • 코드 생성 1회 — 입력 2,000 + 출력 2,000 토큰

월 $7을 전부 쓴다고 할 때, 모델별로 이만큼 됩니다.

모델 입력 / 출력 챗봇 요약 코드
gpt-oss-120b $0.04 / $0.17 98,591회 17,283건 16,666회
Tencent Hy3 $0.06 / $0.21 75,268회 11,965건 12,962회
DeepSeek V4 Flash $0.14 / $0.28 45,454회 5,555건 8,333회
Gemini 2.5 Flash Lite $0.10 / $0.40 41,176회 7,000건 7,000회
GPT-5.6 Luna $0.10 / $0.60 30,434회 6,363건 5,000회
GPT-4o-mini $0.15 / $0.60 27,450회 4,666건 4,666회
DeepSeek V4 Pro $0.43 / $0.87 14,705회 1,806건 2,692회
Gemini 2.5 Flash $0.30 / $2.50 7,777회 1,917건 1,250회

월 1만 원으로 챗봇을 최소 7,777번, 최대 98,591번 돌릴 수 있습니다.

하루 방문자 100명이 각각 세 번씩 대화한다면 월 9,000회입니다. 위 표 어느 모델을 써도 커버됩니다. 개인 서비스나 초기 제품이라면 요금 걱정을 접어도 되는 구간입니다.

2. 왜 12배나 차이가 나나

같은 $7인데 gpt-oss-120b는 98,591회, Gemini 2.5 Flash는 7,777회입니다. 12배 이상 차이가 납니다.

이유는 두 가지가 겹칩니다.

① 단가 자체가 다릅니다. 입력 기준 $0.04와 $0.30은 7.5배 차이입니다.

② 출력 단가 격차가 더 큽니다. $0.17과 $2.50은 약 15배입니다. 그래서 출력이 긴 작업일수록 격차가 벌어집니다.

표에서 코드 생성 열을 보세요. gpt-oss-120b는 16,666회인데 Gemini 2.5 Flash는 1,250회로 13배 차이입니다. 반면 요약 열은 17,283건 대 1,917건으로 9배입니다. 출력이 긴 코드 작업에서 격차가 더 크게 벌어지는 겁니다.

비싼 모델이 나쁘다는 뜻이 아닙니다. 비싼 모델은 어려운 일에만 쓰라는 뜻입니다.

3. 예산 구간별 전략

월 1만 원 ($7) — 검증 단계

아이디어가 되는지 확인하는 구간입니다. 가장 싼 모델 하나로 시작하세요.

  • 모델: gpt-oss-120b, Hy3, DeepSeek V4 Flash 같은 저가 구간
  • 목표: 사람들이 실제로 쓰는지 확인
  • 여기서 품질이 부족하면 그때 올리면 됩니다

이 단계에서 비싼 모델을 쓰는 건 낭비입니다. 아직 쓸 사람이 있는지도 모르는 상태니까요.

월 5만 원 ($35) — 품질 조정 단계

사람이 붙기 시작한 구간입니다. 작업을 나누기 시작합니다.

  • 단순 작업(분류·추출·번역)은 저가 모델
  • 판단이 필요한 작업만 중급 모델(GPT-5.6 Luna, GPT-4o-mini 급)
  • 이 조합이 다음 항목의 라우팅입니다

월 10만 원 ($70) 이상 — 운영 단계

여기서부터는 모델보다 설계가 요금을 결정합니다. 아무리 싼 모델을 써도 대화 히스토리를 안 자르면 요금이 몇 배로 뜁니다. 요금이 뛰는 구조는 AI API 요금 구조 완전 해부에 정리해 뒀습니다.

4. 라우팅 — 같은 예산으로 3.5배 쓰기

가장 효과가 큰 설계입니다. 모든 호출을 같은 모델에 보내지 마세요.

대부분의 서비스에서 요청의 성격은 두 갈래로 나뉩니다.

  • 뻔한 일 — 분류, 추출, 번역, 정형 응답. 전체의 70~90%
  • 어려운 일 — 판단, 추론, 창작. 나머지 10~30%

뻔한 일은 싼 모델로 보내고 어려운 일만 좋은 모델로 보내면 어떻게 되는지 계산해 봤습니다.

전부 Gemini 2.5 Flash로 처리 → $7로 7,777회

80%는 Hy3, 20%만 Gemini 2.5 Flash → $7로 27,515회

같은 돈으로 3.5배를 씁니다. 그리고 어려운 20%는 여전히 좋은 모델이 처리하므로 체감 품질은 거의 그대로입니다.

어떻게 나누나

가장 단순한 방법부터 쓰면 됩니다.

  1. 요청 종류로 나누기 — 버튼이나 메뉴로 이미 구분돼 있다면 그대로 씁니다. 코드 없이 되는 경우가 많습니다
  2. 길이로 나누기 — 입력이 짧으면 저가, 길면 고급으로 보냅니다
  3. 먼저 싼 모델에 보내고 실패하면 올리기 — 저가 모델이 형식을 못 맞추거나 "모르겠다"고 하면 그때만 고급 모델로 재시도합니다

3번이 품질과 비용을 가장 잘 맞춥니다. 다만 재시도가 잦아지면 오히려 더 비싸지므로 재시도 비율을 로그로 확인하세요. 20%를 넘으면 저가 모델을 한 단계 올리는 게 낫습니다.

5. 무료 등급과 섞기

예산을 더 아끼려면 유료 API를 쓰기 전에 무료로 되는 부분을 먼저 걷어내는 방법이 있습니다.

  • 개발·테스트 단계에서는 Google AI Studio 무료 API 키로 붙여 두고, 실서비스 전환 시점에만 유료로 바꿉니다
  • 내부용 도구라면 무료 등급으로 충분한 경우가 많습니다
  • 사용자에게 제공하는 기능만 유료 API로 돌립니다

무료로 어디까지 되는지는 무료 AI 12종 실사용 정리에 정리해 뒀습니다.

6. 예산이 새는 걸 막는 장치

계산대로 안 나오는 경우는 대부분 막아두지 않아서입니다. 서비스를 열기 전에 세 가지만 걸어두세요.

① 사용량 한도(spending limit) 대부분의 공급자가 월 상한을 걸 수 있습니다. 예산의 1.5배쯤으로 잡아두면 사고를 막습니다.

② 출력 토큰 상한 max_tokens를 반드시 지정하세요. 가장 비싼 토큰을 직접 막는 장치입니다.

③ 사용자당 호출 제한 한 사람이 무한정 쓰지 못하게 막습니다. 없으면 한 명이 예산을 다 태울 수 있습니다.

이 셋 중 ①번이 제일 중요합니다. 코드에 실수가 있어도 청구서가 폭발하지 않습니다.

마무리

정리하면 이렇습니다.

  • 월 1만 원($7)으로 챗봇 호출 7,777~98,591회가 가능합니다. 초기 서비스라면 요금 걱정을 접어도 되는 구간입니다
  • 같은 예산인데 모델에 따라 12배 이상 차이가 납니다. 출력이 긴 작업일수록 격차가 커집니다
  • 라우팅 하나로 3.5배를 더 씁니다. 뻔한 일은 싼 모델, 어려운 일만 좋은 모델
  • 예산이 새는 걸 막으려면 사용량 한도부터 걸어두세요

시작할 때 가장 흔한 실수는 처음부터 가장 좋은 모델을 쓰는 것입니다. 검증 단계에서는 싼 모델로 충분하고, 부족하면 그때 올리면 됩니다. 반대 순서는 돈만 쓰고 배우는 게 없습니다.
