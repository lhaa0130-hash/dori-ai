# 팔협 RPG — 버전 보관 규칙

개발노트를 **매일** 올리기 때문에, 각 노트의 "플레이" 링크는 **그 노트를 쓴 날의 빌드**로
영구히 고정되어야 한다. 8월 14일 노트를 반년 뒤에 열어도 8월 14일자 게임이 떠야 한다.
그래야 글에 적힌 내용과 실제로 돌아가는 게임이 어긋나지 않는다.

## 왜 illo.im 에서는 이게 되는가

claude.ai 아티팩트는 **주소가 하나**여서 새로 게시하면 옛 링크도 최신을 보여준다.
illo.im 은 정적 호스팅이라 **경로가 곧 파일**이다.

```
/games/palhyup/2026-08-14/  →  public/games/palhyup/2026-08-14/index.html
```

내일 빌드는 `2026-08-16/` 같은 **다른 폴더**에 들어가므로 위 파일은 건드려지지 않는다.
같은 이름으로 덮어쓰지만 않으면 자동으로 박제된다.

## 폴더 규칙

```
public/games/palhyup/
  2026-08-14/index.html   ← 개발노트 #001 이 가리키는 빌드. ⛔ 절대 덮어쓰지 않는다
  2026-08-16/index.html   ← 다음 노트의 빌드 (새 폴더를 만든다)
  latest/index.html       ← 항상 최신. 배포 때마다 덮어쓴다
```

링크는 두 종류다.

| 어디 | 가리키는 곳 | 성격 |
|---|---|---|
| 개발노트 본문 | `/games/palhyup/<그 날짜>/` | 🔒 영원히 그날 버전 |
| 개발노트 본문(작게) | `/games/palhyup/latest/` | 🔄 계속 바뀜 |
| 프로젝트 페이지 "게임 실행" | `/games/palhyup/latest/` | 🔄 늘 최신 |

## 새 개발노트를 올릴 때

1. `public/games/palhyup/<YYYY-MM-DD>/index.html` 에 그날 빌드를 **새로** 넣는다
   (⛔ 기존 날짜 폴더는 손대지 않는다 — 옛 노트의 링크가 그 파일을 가리키고 있다)
2. 같은 파일을 `public/games/palhyup/latest/index.html` 에 **덮어쓴다**
3. 새 글 `content/reports/report-NN.md` 를 쓰고 링크 두 개를 건다
   - 고정: `/games/palhyup/<YYYY-MM-DD>/`
   - 최신: `/games/palhyup/latest/`
4. `constants/projectsData.ts` 의 palhyup `docHref` 를 새 개발노트로 바꾼다
   (`launchHref` 는 `/latest/` 고정이라 손댈 필요 없다)

## 글의 말투

개발노트는 **평서체(~다)** 로 쓴다. 사이트의 다른 글은 "~습니다" 지만 이건 개인 개발일지라
그 편이 자연스럽다. 실제로 저자가 그렇게 썼다.

## 왜 단일 파일인가

게임은 외부 요청이 하나도 없는 자체 완결 HTML 이다(스크립트·이미지·소리 전부 인라인,
효과음도 파일 없이 브라우저에서 합성한다). 그래서 폴더째 복사해 두면 그 시점 버전이
그대로 박제된다. 빌드 과정도, 의존성도, 깨질 외부 링크도 없다.

## 주의

`/games/` 경로는 robots.txt 로 크롤링을 막아 두었다(app/robots.ts).
게임 화면은 캔버스라 읽을 텍스트가 없어 색인 가치가 없고, 날짜별로 쌓이면 같은 내용이
여러 URL 로 중복되기 때문이다. **사람이 링크를 눌러 들어가는 데에는 아무 지장이 없다.**
읽을거리는 개발노트(인사이트 기사) 쪽이 담당한다.
