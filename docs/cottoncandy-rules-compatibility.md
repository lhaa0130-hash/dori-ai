## 0. 에뮬레이터 실행 환경 (재실행 명령)

이 머신에는 **JDK 17 만** 있고 JDK 21+ 는 없다(전수 확인: `C:\src\jdk` 만 존재).
전역 `firebase` CLI 는 v15.19.0 이라 **JDK 21 이상을 요구**해 에뮬레이터가 기동하지 않는다.

> 임의로 JDK 를 내려받지 않았다. 대신 이 프로젝트가 이미 쓰던 **firebase-tools@13**(Java 17 지원,
> npx 캐시에 13.35.1 존재)로 `emulators:exec` 를 고정했다. 이것은 우회가 아니라
> **원래 동작하던 구성으로 되돌린 것**이다(전역 CLI 업그레이드가 스위트를 깨뜨린 상태였다).

```bash
npm run test:my-world:emulator
```

사람이 직접 재실행할 때:

```bash
npx --yes firebase-tools@13 emulators:exec --only auth,firestore --project demo-illo-myworld "npm run test:my-world:emulator:run"
```

JDK 21+ 를 설치하면 전역 CLI 로도 돌아간다. **미실행을 PASS 로 처리하지 않았다** — 위 명령으로 실제 실행했다.

## 3. 롤백 안전성

| 롤백 | 결과 조합 | 안전한가 |
|---|---|---|
| Cloudflare 이전 deployment 로 되돌리기 (Functions+client 동시) | 조합 1 또는 6 | Rules 미배포 상태면 **안전**(조합 1). Rules 배포 후면 **위험**(조합 6) |
| `CANDY_ROLLOUT_MODE=off` + 재배포 | 조합 2/4/5 유지, 신규 재화 경로만 차단 | ✅ **가장 안전한 킬스위치** |
| main revert + 재배포 | 조합 1 | Rules 미배포 시 안전 |
| client 만 롤백 | 조합 3(Rules 배포 후) | 🔴 위험 |
| Rules 만 롤백 | 조합 4 | ⚠️ 보안 창이 다시 열림(기능은 정상) |

> **Rules 를 배포한 뒤에는 client 를 되돌리면 안 된다.** 되돌려야 한다면 **Rules 를 먼저** 되돌린다.
> 즉 **롤백 순서는 배포 순서의 역순**이다: Rules → client → Functions.

## 4. 배포 순서에 대한 반박 검토

기존 runbook 은 "코드 먼저, Rules 마지막"이다. 이번 실측으로 근거가 확정됐다.

| 순서안 | 위험 |
|---|---|
| Rules → client | 🔴 조합 3 — 구버전 사용자 전원이 재화 기능 실패 |
| client → Rules (**권고**) | ⚠️ 조합 4 구간에 콘솔 공격 창. 간격을 짧게 |
| client 와 Rules 동시 | 이론상 최선이나 **두 시스템이 분리돼 있어 원자적으로 불가**. 실패 시 어느 쪽이 반영됐는지 불명확해 더 위험 |

### 조합 4 구간을 줄이는 실무 방법

1. `deploy.js` 실행 → 라이브 buildId 변경 확인 → **즉시** Rules 배포(연속 작업, 사이에 다른 일 끼우지 않기)
2. 그 사이 `CANDY_ROLLOUT_MODE` 는 이미 `all` 이어야 한다(그래야 신규 client 가 403 을 안 받는다)
3. 트래픽이 적은 시간대(새벽)에 수행
