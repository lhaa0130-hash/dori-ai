## 노출 규모

- **최대 피해**: 카나리 UID 1개당 **하루 +50 솜사탕**(정상 50 → 100)
- **누적 조건**: 매일 미니게임 60초 체류
- **다른 재화 경로**: `/api/purchase`·`/api/admin/grant` 는 **구버전 client 가 호출하지 않는다**(git grep 0건) → 트래픽 0
- **결함 A(장착 우회)**: 선재 결함이며 **모든 사용자에게 이미 열려 있었다**. Functions rollback 으로 달라지지 않는다(클라+Rules 문제)

## rollback vs freeze 비교

| | Functions rollback | 카나리 freeze (권고) |
|---|---|---|
| 이중 지급 차단 | ✅ | ✅ (행동을 안 하면 발생 안 함) |
| 부작용 | `/api/purchase`·`/api/admin/grant` 소멸(현재 트래픽 0이라 무해하나 상태가 되돌아감) | 없음 |
| 결함 A 에 대한 효과 | **없음** | 없음 |
| 재작업 비용 | 병합 관찰·검증을 다시 해야 함 | 0 |
| 위험 | 배포 조작이 하나 더 늘어난다 | 사용자 절제에 의존 |

→ **피해 상한이 하루 +50, 대상이 소유자 본인 계정 1개**인데 배포 조작을 추가하는 것은 이득보다 위험이 크다.
