## 2. 키보드 경로 — 실제 키 이벤트로 추적

### Tab 순서 (390px, My World 내부 11개)

```
1  대표 캐릭터 바꾸기 (아바타)
2  효과음 끄기
3  침대 살펴보기
4  책상 살펴보기
5  화분 살펴보기
6  도리 터치하기 (두 번 누르거나 길게 누를 수 있습니다)
7  쓰다듬기 — 쓰다듬어 친밀도를 올려요
8  인사하기 — 인사를 건네요
9  선물하기 — 선물을 줘요
10 재우기 — 잠자리에 들게 해요
11 로그인하고 이어서 키우기 →
```

- **시각 순서와 DOM 순서가 일치**한다(위→아래, 방 안 가구 → 캐릭터 → 행동 → CTA).
- 포커스 표시(outline/box-shadow)가 없는 요소 **0개**.
- `Shift+Tab` 역방향 정상 동작 확인.

### 방 꾸미기 모달 — 마우스 없이 끝까지

| 단계 | 결과 |
| --- | --- |
| 모달 열림 직후 포커스 | `닫기` 버튼 (dialog 내부) ✓ |
| Tab 으로 가구 도달 | `러그. Enter 로 선택합니다.` ✓ |
| `Enter` 로 선택 | `aria-pressed="true"` + `러그 — 선택됨. 방향키로 옮기고 Delete 로 지웁니다.` ✓ |
| 선택 후 편집 컨트롤 | 옮기기·회전·삭제 등 **7개** 노출 ✓ |
| `ArrowRight` 로 이동 | `left: 50%` → `51%` ✓ |
| `Escape` (변경 있음) | `저장하지 않은 변경사항이 있어요` 확인 다이얼로그 — **몰래 취소하지 않는다** ✓ |
| 포커스 복귀 | 확인 다이얼로그가 열려 있어 그 안에 머문다(정상). 모달을 완전히 닫으면 여는 버튼으로 복귀(`RoomEditorModal` 의 `prev?.focus()`) |

**결론: 방 가구 선택·이동·삭제와 캐릭터 상호작용을 마우스 없이 완주할 수 있다.**

## 3. 색 대비 (WCAG) — 실측

Tailwind v4 는 `oklch()` 로 색을 내보내므로 정규표현식 파싱이 불가능하다.
canvas 2D 컨텍스트로 어떤 CSS 색 표기든 sRGB 로 정규화한 뒤 WCAG 상대휘도 공식을 적용했다.

### 결과

| 시점 | 검사한 텍스트 | AA 미달 | 최저 대비 |
| --- | --- | --- | --- |
| 수정 전 | 54개 | **13개** | 2.23 |
| 수정 후 | 54개 | **0개** | **4.51** |

### 수정 내역

| 용도 | 이전 | 대비 | 이후 | 대비 |
| --- | --- | --- | --- | --- |
| 크림 위 오렌지 텍스트 | `#E07C2E` | 2.96 | `#9A4E14` | **6.04** |
| 채워진 CTA 배경(흰 글자) | `#F9954E` | 2.23 | `#AD5B18` | **4.92** |
| CTA hover | `#f0862f` | 3.2 | `#8F4A12` | — |
| 감정 칩 | 파스텔 배경 + 흰 글자 | 2.65 | 파스텔 배경 + `#3A2A1B` + 흰 링 | AA 통과 |
| 아바타 편집 배지 | `#F9954E` + 흰 글자 | 2.23 | `#9A4E14` + 흰 글자 | **6.04** |
| 보조 문구 | `stone-400` | 2.59 | `stone-500/600` | AA 통과 |
| 수치 텍스트 | `pink-600` / `amber-600` | 4.28 | `pink-700` / `amber-700` | AA 통과 |

### 트레이드오프 (기록)

`#F9954E` → `#AD5B18` 은 **브랜드 오렌지보다 어두운 테라코타**다. AA 를 통과하지만 버튼이 눈에
띄게 진해진다. 대안은 ① 오렌지를 유지하고 글자를 어두운 갈색으로 ② 사이트 전역 2단 토큰 도입.
사이트 전역 `bg-[#F9954E]`(285곳)이 같은 문제를 갖고 있어 브랜드 결정이 필요하다
→ `docs/site-design-followups.md` P1 에 실측값과 함께 기록했다.

### 색만으로 상태를 전달하지 않는다 (실측 근거)

| 상태 | 색 | 함께 제공하는 정보 |
| --- | --- | --- |
| 저장됨 | emerald | `✅` + "저장됨" |
| 수정됨 | 오렌지 | `✏️` + "저장 안 된 변경 있음" |
| 저장 실패 | red | `⚠️` + "저장 실패" + `role="alert"` 문구 |
| 체험 모드 | stone | `🔓` + "체험 모드 · 로그인하면 저장돼요" |
| cooldown | 흐림 | "N초 후" 텍스트 + 진행 띠 + `aria-label` |
| 선택된 가구 | 주황 실선 | `aria-pressed="true"` + "선택됨" 문장 |
| 키보드 포커스 | 주황 **점선** | 선택(실선)과 시각적으로 구별 |
| 감정 | 감정색 | 이모지 + 라벨("편안" 등) + `title` |

## 5. `aria-live` 사용 (같은 문구 반복 낭독 방지)

| 영역 | 역할 | 정책 |
| --- | --- | --- |
| 말풍선 | 캐릭터 대사 | `role="status" aria-live="polite" aria-atomic="true"` — 문구가 바뀔 때만 |
| 안내·제한 | 로그인·cooldown·상한 | `aria-live="polite" aria-atomic="false"` — 목록에 추가될 때만, 2.4초 후 자동 제거 |
| 세계 알림 | 저장 실패 | `aria-live="polite"` — 상태가 존재할 때만 렌더(없으면 DOM 에서 제거해 재낭독 방지) |
| 저장 상태 배지 | 저장됨/수정됨/실패 | `aria-live="polite"` 단일 노드 교체 |

상승 피드백(`RisingRewards`)은 `aria-hidden` 이다 — 같은 수치가 알림으로도 낭독되면 중복이므로
시각 효과만 담당한다.
