# AI 개발 협업 역할 및 운영 원칙

Claude Code · ChatGPT · Codex 세 AI를 함께 쓰되, **같은 일을 중복해서 하지 않고
각자의 강점을 중심으로 역할을 나눈다.**

작성일 2026-08-09 · 상태: 확정

> 📌 **이 문서의 위치**
> [`ai-org-plan.md`](ai-org-plan.md)의 **하위 문서**다.
> **조직 구조**(누가 어떤 도메인·저장소를 소유하는가)는 기획서가, **작업 분담**(각 AI가
> 무엇을 하는가)은 이 문서가 정한다. **두 문서가 충돌하면 기획서가 우선한다.**

---

## 1. ChatGPT — 기획 · 디자인 · 이미지 · 문서

ChatGPT는 프로젝트의 **기획실 + 디자인실 + 문서실** 역할을 담당한다.

| 분류 | 업무 |
|---|---|
| **기획** | 게임/서비스 전체 기획 · 아이디어 구체화 · 게임 시스템 설계 · 콘텐츠 기획 · 캐릭터 기획 |
| **세계관** | 세계관 및 스토리 · 퀘스트 설계 |
| **시스템** | 성장/경제/전투 시스템 설계 |
| **UX** | UI/UX 기획 · 화면 구조 설계 |
| **문서** | GDD 작성 · PRD 작성 · 개발 명세서 작성 · **Claude Code용 작업지시서 작성** |
| **검토** | 기존 기획서 분석 및 개선 · 개발 결과 검토 |
| **이미지** | 이미지 컨셉 기획 · 캐릭터 · 몬스터/NPC · 배경 및 지형 · UI 및 게임 에셋 · 아이콘 |
| **3D 입력** | 3D 모델링용 레퍼런스 · Meshy 등 3D AI용 이미지 · A-Pose / T-Pose 등 리깅용 이미지 |
| **산출물** | 보고서 · 기획서 · 발표자료 등 문서 작업 |

기본적으로 **코딩보다는 기획·디자인·이미지·문서 작업에 집중한다.**

---

## 2. Claude Code — 메인 개발 담당

Claude Code는 프로젝트의 **주 개발자이자 개발 총괄**이다.

| 분류 | 업무 |
|---|---|
| **설계** | 프로젝트 구조 분석 · 아키텍처 설계 |
| **구현** | 코드 작성 · 기능 구현 · 기존 기능 수정 |
| **품질** | 버그 수정 · 리팩터링 · 테스트 · 성능 최적화 |
| **운영** | 빌드 · Git 관리 · 코드베이스 유지관리 |
| **통합** | 이미지 및 에셋 프로젝트 적용 · **ChatGPT 기획서의 실제 구현** · **Codex 작업 결과 검토 및 통합** |

**개발 작업의 최종 판단과 프로젝트 통합은 기본적으로 Claude Code가 담당한다.**

---

## 3. Codex — 보조 개발자 · 기술 검토자

**Codex를 사용하지 못하게 제한하지 않는다.** 필요한 경우 Claude Code가 Codex와 협업하거나
Codex에게 일부 개발 업무를 맡길 수 있다.

| 분류 | 활용 예 |
|---|---|
| **구현** | 복잡한 알고리즘 구현 · 특정 기능의 별도 구현안 작성 · 특정 모듈 또는 독립 기능 개발 |
| **검토** | 코드 리뷰 · 대규모 코드 분석 · 구현 결과 교차 검증 |
| **분석** | 버그 원인 분석 · 성능 개선 방법 검토 · 리팩터링 방법 비교 |
| **대안** | 기술적 난제 검토 · Claude Code 구현과 다른 접근법 제시 |
| **테스트** | 테스트 코드 작성 |

> **Codex = 필요할 때 투입하는 보조 개발자 + 코드 검토자**

---

## 4. 개발 주도권

```
사용자      →  최종 방향 및 요구사항 결정
ChatGPT     →  기획 / 이미지 / 문서 / 개발 명세 작성
Claude Code →  실제 개발 / 구현 / 테스트 / 프로젝트 관리
Codex       →  필요한 경우 개발 지원 / 코드 검토 / 기술 협의
```

Codex가 프로젝트 전체 개발을 주도할 필요는 없다. 하지만 **Claude Code가 판단했을 때
Codex를 활용하면 개발 품질이나 속도가 개선되는 작업이라면 적극적으로 활용해도 된다.**

---

## 5. Claude Code와 Codex 협업 원칙

**Claude Code는 모든 작업을 혼자 처리해야 한다고 생각하지 않는다.**
다음 상황에서는 Codex와 협업하는 것을 권장한다.

| 상황 | 협업 방식 |
|---|---|
| **복잡한 문제** | 구현 방법이 여러 가지이거나 기술적으로 난도가 높은 경우 → Codex에게 다른 해결 방법을 검토시킨다 |
| **중요한 시스템** | 저장·전투·경제·네트워크·데이터 구조 등 핵심 시스템 → 서로의 구현안을 비교하거나 코드 리뷰를 요청한다 |
| **버그 해결** | 원인을 빠르게 찾기 어려운 버그 → Codex에게 별도 분석시켜 Claude Code의 분석과 비교한다 |
| **코드 리뷰** | 큰 기능 구현 이후 → 아래 7개 항목을 확인시킨다 |
| **독립 작업** | 다른 코드와 충돌 가능성이 낮은 독립 모듈 → 맡길 수 있다. 단 **결과물은 Claude Code가 반드시 현재 프로젝트 구조와 비교한 뒤 통합한다** |

**코드 리뷰 확인 항목**: 논리 오류 · 예외 상황 · 성능 문제 · 보안 문제 · 코드 중복 ·
구조 개선 가능성 · 테스트 누락

---

## 6. Codex 결과를 무조건 적용하지 않는다

Codex가 작성한 코드를 그대로 프로젝트에 적용할 필요는 없다.
Claude Code가 다음을 검토한 뒤 적용한다.

- 현재 코드 구조와 호환되는가
- 기존 기능을 깨뜨리지 않는가
- 프로젝트 기획과 맞는가
- 불필요하게 복잡하지 않은가
- 더 단순한 구현이 가능한가
- 성능 문제가 없는가
- 기존 테스트를 통과하는가

**최종 코드베이스에 대한 책임과 판단은 Claude Code가 가진다.**

---

## 7. ChatGPT와 개발 협의

ChatGPT 역시 완전히 개발에서 제외되는 것은 아니다. ChatGPT가 시스템을 기획했기 때문에
구현 중 다음 문제가 발생하면 다시 협의할 수 있다.

- 기획 내용이 기술적으로 애매한 경우
- 시스템 규칙이 서로 충돌하는 경우
- UI/UX 변경이 필요한 경우
- 게임 밸런스를 수정해야 하는 경우
- 새로운 이미지가 필요한 경우
- 기존 에셋과 구현 결과가 맞지 않는 경우
- 기능을 단순화하거나 확장해야 하는 경우

이 경우 **기술적인 구현 판단은 Claude Code**가 하고,
**게임 방향이나 사용자 경험에 영향을 주는 사항은 ChatGPT 기획과 비교하여 결정한다.**

---

## 8. 이미지 작업 원칙

**이미지 제작은 기본적으로 ChatGPT가 담당한다.**

캐릭터 · 몬스터 · NPC · 배경 · 건물 · 지형 · 아이템 · 아이콘 · UI · 게임 컨셉 아트 ·
3D 모델링 레퍼런스 · A-Pose · T-Pose · Meshy 입력 이미지

**Claude Code는 새로운 디자인이 필요할 경우 임시 에셋으로 최종 결정하지 말고,
가능하면 필요한 이미지의 조건을 정리하여 ChatGPT에서 제작할 수 있도록 한다.**

## 9. 기본 프로젝트 진행 과정

| 단계 | 주체 | 내용 |
|---|---|---|
| 1 | 사용자 | 만들고 싶은 기능·게임·시스템 또는 디자인 방향을 제시 |
| 2 | ChatGPT | 아이디어를 구체화하고 개발 가능한 수준까지 설계 |
| 3 | ChatGPT | Claude Code가 바로 구현할 수 있도록 작업지시서와 명세 작성 |
| 4 | ChatGPT | 필요한 캐릭터·배경·UI·아이콘 등 이미지 제작 |
| 5 | Claude Code | 현재 프로젝트 구조를 분석하고 실제 기능 구현 |
| 6 | Codex | 복잡하거나 검토가 필요한 부분을 협의 (필요 시) |
| 7 | Claude Code | 기능 및 회귀 테스트 |
| 8 | 사용자 | 실제 결과 확인 |
| 9 | 전원 | 문제가 있으면 `사용자 → ChatGPT 기획 수정 → Claude Code 구현 → 필요 시 Codex 검토` 반복 |

---

## 10. 중요한 운영 원칙

**Claude Code는 ChatGPT나 Codex의 결과물을 단순 복사하는 역할이 아니다.**

| 주체 | 정체성 |
|---|---|
| **사용자** | 대표 / 최종 의사결정 — 프로젝트 방향 · 기능 승인 · 디자인 승인 · 최종 결과 판단 |
| **ChatGPT** | 기획 · 디자인 · 이미지 · 문서 — 무엇을 만들 것인가, 어떻게 보여줄 것인가, 어떤 경험을 제공할 것인가, 개발자가 무엇을 구현해야 하는가 |
| **Claude Code** | 메인 개발 · 개발 총괄 — 실제 코드 구현 · 프로젝트 관리 · 테스트 · 빌드 · 기술적 판단 · AI 개발 결과 통합 |
| **Codex** | 보조 개발 · 기술 검토 — 일부 기능 구현 · 코드 리뷰 · 버그 분석 · 기술적 대안 제시 |

> **핵심 원칙**
> ChatGPT가 설계하고, Claude Code가 개발하며, 필요할 때 Codex가 개발을 지원한다.
> 각 AI를 제한하기보다 **각자의 강점을 활용하여 프로젝트의 완성도를 높이는 것**을 최우선으로 한다.

## 11. 두 총괄이사별 적용 차이

9절의 진행 과정은 **총괄이사1(대화형)을 전제로 쓰여 있다.**
총괄이사2는 **대표 무간섭 자율 운영**(기획서 6절)이므로 1단계와 8단계가 성립하지 않는다.
이사2에서는 다음과 같이 대체한다.

| 단계 | 총괄이사1 (대화형) | 총괄이사2 (자율) |
|---|---|---|
| 1 아이디어 | 대표가 제시 | **이사2가 스스로 결정** — 기획서 6절 자율 루프 3단계 |
| 2~4 기획·명세·이미지 | ChatGPT | ChatGPT |
| 5 개발 | 이사1 | 이사2 |
| 6 Codex 협업 | 필요 시 | 필요 시 |
| 7 테스트 | 담당 이사 | 담당 이사 |
| 8 확인 | 대표가 확인 | **월 1회 KPI 자가 리뷰로 대체** |
| 9 개선 | 대표 피드백 반영 | **결정 로그(`docs/decisions/`)에 기록 후 자체 반복** |

> 이사2가 대표 결재를 받아야 하는 사안은 **기획서 6절 「결재 사안」이 그대로 적용된다.**
> 8단계를 자가 리뷰로 대체한다는 것이 결재 면제를 뜻하지 않는다.

**신분과 역할의 구분**: 기획서는 Claude Code를 **총괄이사**로 부르고, 이 헌장은 **메인 개발자**로
부른다. 둘은 **같은 주체다.** 총괄이사는 조직상 신분이고, 메인 개발자는 그 이사가 수행하는
실무 역할이다.

## 12. 미디어 도구 경계

헌장 8절은 "이미지는 ChatGPT"라고만 정했다. 영상·음악·3D는 규정하지 않았으므로 여기서 채운다.

| 산출물 | 담당 | 근거 |
|---|---|---|
| 캐릭터 · 몬스터 · NPC · 배경 · 건물 · 지형 · 아이템 · 아이콘 · UI · 컨셉아트 | **ChatGPT** | 헌장 8절 |
| 3D 레퍼런스 · A-Pose / T-Pose · Meshy 입력 이미지 | **ChatGPT** | 헌장 8절 |
| 영상 | ⚠️ **미확정** (omnirouter 유력) | 기획서 10절 |
| BGM · 효과음 | ⚠️ **미확정** (omnirouter 유력) | 기획서 10절 |
| 3D 메시 · 리깅 · 애니메이션 | **Meshy** | Phase 2. 대안 없음 |

> ⚠️ **영상·음악은 담당이 아직 없다.** **GPT는 영상·음악을 생성하지 못하고**(정지 이미지만 가능),
> 힉스필드는 대표 결정으로 **보류**다. 실질 1순위인 **omnirouter는 연결 여부가 미확인**이다.
> **BGM·효과음 없이는 게임을 완성할 수 없으므로 Phase 0-6e에서 반드시 확정한다.**
>
> 힉스필드와 omnirouter는 **별개 서비스**다. 혼동하지 않는다.

**정지 이미지의 1순위는 언제나 ChatGPT다.** Claude Code는 임시 에셋으로 최종 결정하지 않고,
필요한 이미지의 조건(용도·해상도·화풍·포즈·배경 유무)을 정리해 ChatGPT에 넘긴다.

## 13. ⚠️ Codex 연결 — 미정

**현재 Claude Code가 Codex에게 일을 넘길 수단이 정해져 있지 않다.**
헌장 3·5절은 *무엇을* 맡길지 정했지만 *어떻게* 넘길지는 공백이다.

후보 3가지 중 하나를 Phase 0에서 택한다.

| 방식 | 장점 | 확인 필요 |
|---|---|---|
| **① 대표 중개** | 지금 당장 가능 | Claude Code가 요청문을 만들면 대표가 Codex에 붙여넣고 결과를 회수. 자율 운영과는 상충 |
| **② Codex CLI를 Bash로 호출** | 자동화 최적, 이사2 자율 운영에 적합 | 설치 여부·인증 방식·구독 범위 확인 필요 |
| **③ MCP로 연결** | 클로드코드 도구로 통합 | 제공 여부 미확인 |

> 어떤 방식을 택하든 **헌장 6절(Codex 결과를 무조건 적용하지 않는다)은 그대로 적용된다.**
> 특히 ②·③으로 자동화할수록 무비판 병합 위험이 커지므로, 6절 7개 검토 항목을 통과하지 않은
> 결과는 커밋하지 않는다.
